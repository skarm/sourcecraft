# Спецификация API

[English](README.md) · [Русский](README.ru.md)

`sourcecraft.swagger.json` — снимок официальной спецификации публичного REST API
SourceCraft, загруженный 2026-11-04:
https://api.sourcecraft.tech/sourcecraft.swagger.json

Источник и описание авторизации:
https://sourcecraft.dev/portal/docs/en/sourcecraft/operations/api-start

Версия в документе: `0.0.1`. Этот номер сам по себе не фиксирует состав методов:
SDK привязан к сохранённому файлу. В текущем снимке 268 методов и 282 определения
моделей, включая модели событий. Методы из раздела `Withdrawn` сохранены для
совместимости и помечены `Deprecated`.

Генератор учитывает `requestBody` с multipart, хотя основной документ имеет
формат Swagger 2.0. Вложение релиза по тегу требует отдельного поля `name`.

Обновление выполняется явно:

```sh
curl --fail --show-error --location https://api.sourcecraft.tech/sourcecraft.swagger.json -o api/sourcecraft.swagger.json
go generate ./...
go test ./...
```

Для сборки и генерации требуется Go 1.26 или новее. При установленном
совместимом toolchain сборка и генерация SDK не обращаются в сеть. Генератор
проверяет поддерживаемые конструкции используемого подмножества схемы;
изменения API требуют проверки сгенерированного кода перед выпуском.

## AppSec OpenAPI

`appsec.openapi.json` — официальный JSON-снимок отдельного API безопасности
AppSec OpenAPI 3.1.0, загруженный 2026-11-04. Исходный endpoint
https://appsec.sourcecraft.tech/openapi возвращает JSON при заголовке
`Accept: application/json` и YAML без этого заголовка. В снимке 27 операций
и 66 определений моделей. Файл сохранён без преобразования содержимого.

Обновление AppSec:

```sh
curl --fail --show-error --location -H 'Accept: application/json' https://appsec.sourcecraft.tech/openapi -o api/appsec.openapi.json
go generate ./...
go test ./...
go run ./internal/generate -spec api/appsec.openapi.json -check
```

Схема AppSec не содержит `operationId`. Стабильные Go-имена операций явно заданы
в `internal/generate/appsec.go`; неизвестный маршрут останавливает генерацию,
чтобы новые операции не пропускались. Generated-файлы AppSec —
`appsec_api_gen.go` и `appsec_models_gen.go`. Общий CLI определяет формат по
`swagger`/`openapi` и использует отдельный компилятор AppSec, написанный на
стандартной библиотеке Go. Обновление одного снимка не переписывает файлы другого.

Компилятор поддерживает nullable-свойства моделей, `anyOf` с `null` в свойствах,
`allOf` для enum с default, циклические ссылки, словари в свойствах с произвольным JSON,
числовые ID и multipart с optional-полями. Это специализированное подмножество
OpenAPI 3.1, а не универсальный OpenAPI-генератор. Nullable query-параметры можно
пропускать через `nil`: default применяет сервер, а явно переданные `0`, `false`
и пустая строка сохраняются. Для query-полей с value-типом генератор подставляет
объявленный default вместо нулевого значения.
Ограничения полей запросов, не проверенные SDK, проверяет сервер.

Генерация отклоняет nullable-ответ целиком, словарь в корне определения модели
и несовместимые успешные ответы одного метода (например, типизированный JSON
для `200` и отсутствие тела для `202`). Эти конструкции требуют отдельной
поддержки. Для загрузки отчётов схема задаёт нетипизированный JSON `200` и пустой
`202`; оба варианта поддерживаются. Регрессии проверяют, что неподдерживаемые
изменения завершаются ошибкой до записи файлов.

Тесты AppSec независимо читают сохранённую спецификацию, вызывают все 27 методов,
проверяют все 66 моделей, nullable-поля, numeric precision и оба статуса загрузки
отчёта (`200`/`202`). Дополнительные маленькие OpenAPI-схемы компилируются как
независимые Go-пакеты. Приватный live API без токена не проверяется.

## Компилятор платформенного Swagger

`internal/generate` остаётся одним внутренним командным пакетом. `main.go`
обрабатывает флаги, читает схему, проверяет или записывает файлы. Функция
`generate` в `generate.go` принимает JSON и возвращает оба готовых Go-файла в
памяти; схема и правила типов находятся в `schema.go`, имена — в `names.go`,
модели — в `models.go`, методы и query-параметры — в `operations.go`.

Перед записью подготавливаются оба файла и проверяются существующие выходные
пути. Каталог вместо одного из выходных файлов отклоняется до изменения другого.
Несколько записей не образуют файловую транзакцию: сбой диска или изменение
файлов другой программой может потребовать повторной генерации.

`operationId` должен быть допустимым экспортируемым Go-идентификатором, чтобы
метод был доступен потребителям SDK. Проверка объявлений
отклоняет коллизии между выходными файлами и ручным runtime SDK. JSON-имена,
которые стандартный encoder не может выразить через struct tag, и смешанные
объекты со статическими properties и динамическими ключами отклоняются явно.
Префикс `AppSec` в именах типов и констант закреплён за отдельным AppSec API,
поэтому платформенная схема не может создать объявление в его пространстве имён.

Тесты компилируют небольшие независимые схемы для GET, JSON с датами, POST с
query-параметрами, DELETE и multipart. Они дополняют проверку текущего снимка,
проверяют отсутствие лишних импортов и не изменяют SDK при запуске `-check`.

## Стабильность публичных Go-типов

Канонические модели платформы используют явную политику из
`internal/generate/platform_types.json`, встроенную в генератор через `go:embed`.
Для 241 существующего объектного определения сохранено исходное представление
optional-полей; у 64 из них optional-скаляры остаются указателями. Новая модель
по умолчанию использует значения для optional-скаляров. Обход API-запросов не
меняет эту политику и существующие модели.

Если входное использование требует указателей для различения пропущенных и
нулевых значений, создаётся отдельный `<Model>Input`. Проекции распространяются
через вложенные объекты, массивы, словари и циклические ссылки. Новый метод
принимает входную проекцию; ответ использует каноническую модель. Например,
добавление метода с `Branch` в body создаст `BranchInput.Name *string` и сохранит
`Branch.Name string`. Совпадение имени проекции с существующим объявлением
отклоняется до записи файлов. AppSec использует собственные стабильные правила.

Снимок [public-api.golden](public-api.golden) фиксирует 1122 публичных объявления
обоих клиентов: типы, экспортируемые поля и их порядок/теги, сигнатуры и методы,
константы с точными значениями, aliases и ограничения параметров типов.
Сравнимость типов также проверяется, поскольку изменение private-поля может
сделать публичный тип непригодным для `==` или ключа map. Имена аргументов,
документация и private-поля сами по себе не считаются публичным контрактом.

```sh
go run ./internal/apicheck
```

Проверка читает настоящие compiler export data через `go/types`. Она отклоняет
удаление или изменение зафиксированного объявления. Новые объявления разрешены;
добавление поля существующей структуры требует явного рассмотрения и обновления
снимка. Это консервативный контроль исходного API; изменение поведения API на
сервере он не классифицирует. Команда выполняется в обоих CI workflow и тестах.

После анализа изменений снимок обновляется только явной командой:

```sh
go run ./internal/apicheck -update
```

Добавленные объявления следует включать в снимок после ревью, чтобы последующие
изменения также контролировались. `go generate`, обычная проверка и CI не
перезаписывают политику или baseline. Изменение правил существующих моделей или
обновление baseline, скрывающее несовместимость, требует отдельного решения
о миграции потребителей.

## Проверка всех опубликованных контрактов

[contracts.json](contracts.json) перечисляет все снимки в `api/`, их стабильные
имена и официальные URL. Сейчас это основной Swagger и AppSec OpenAPI; модели
событий входят в основной Swagger. При добавлении нового JSON-снимка добавьте
его в реестр. Проверка отклоняет JSON-снимки, отсутствующие в реестре.

Отдельный workflow [.github/workflows/contracts.yml](../.github/workflows/contracts.yml)
имеет ручной запуск `workflow_dispatch` и ежедневное расписание `23 4 * * *`
(04:23 UTC). Он работает независимо от основного CI и не требует PAT SourceCraft.
Помимо загрузки схем workflow выполняет `go test -count=1 ./...`, включая
контракты всех методов/моделей и соответствие generated-файлов обоим снимкам.
Локальные тесты и публикация отчёта выполняются также при обнаруженном изменении
или ошибке загрузки одного из контрактов.

Для запуска локально нужны Go 1.26+ и Git:

```sh
go run ./internal/checkcontracts
go run ./internal/checkcontracts -out /tmp/sourcecraft-contracts
```

Каталог отчёта должен отличаться от каталога снимков. При повторном запуске
старые diff и canonical-снимки каждого контракта удаляются, чтобы ошибка загрузки
не оставляла в новом отчёте данные предыдущей проверки.

Без `-out` создаётся новый временный каталог. Проверка читает каждый документ
целиком: маршруты, методы, модели и события, поля и enum, параметры, request body,
ответы, авторизацию, версию и описания. Игнорируются пробелы и порядок ключей
объектов. Порядок массивов и текст чисел сохраняются; большие числа не
преобразуются в `float64`. Любое различие, включая изменение описания, считается
изменением контракта; автоматической классификации breaking/non-breaking нет.

Для каждого успешно загруженного контракта отчёт содержит `<name>.local.json`
и `<name>.published.json`, а при изменении — `<name>.diff`. Общий `summary.md`
различает `unchanged`, `CHANGED` и `ERROR`. Все контракты проверяются даже при
ошибке одного из них. Ненулевой exit code возвращается как при различиях, так
и при ошибке загрузки/разбора; сетевой сбой не считается совпадением схем.
HTTP-запрос ограничен 30 секундами, размер документа — 32 MiB.

В GitHub Actions отчёт публикуется в summary и артефакте `api-contracts`, который
хранится 14 дней. Снимки и SDK автоматически не обновляются. После анализа diff
обновление выполняется явно командами, приведёнными выше.
